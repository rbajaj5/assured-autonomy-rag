# Safe Assurance Evaluator Operating Notes

Autonomy assurance proposals should be bounded, non-operational, auditable, and non-interfering with real people or infrastructure. A safe proposal defines the system boundary, the evaluation environment, the data sources, the decision authority, and the conditions under which the experiment must stop.

## Sandbox Requirement

Adversarial-agent examples are acceptable only as synthetic stress-test cases. A valid sandbox prohibits live cyber access, physical actuation, real targeting data, operational recommendations, and deployment outside the test environment. Synthetic actors and fictional geography should be used when testing risky agent behavior.

## Audit and Replay

Assurance experiments should produce logs, run manifests, model/configuration identifiers, deterministic replay artifacts, and reviewable outputs. Human oversight must include authority to pause, reject, or deactivate the experiment rather than merely observe it.

## Refusal Boundary

Proposals involving invasion, attack, real-world targeting, cyber intrusion, exploit generation, weaponization, live-system control, or geopolitical operational planning should be rejected or rewritten into a boxed defensive simulator with no operational utility.
